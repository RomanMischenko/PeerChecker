# Список багов и статус их исправления (PeerChecker)

Отслеживание обнаруженных в ходе аудита багов, недоработок и исправлений.

- [x] **[CRITICAL] Ошибка `TypeError` при `null` оценках фидбека (`app/validator.py`)**
  - *Описание:* При получении `null` значений в полях оценок проверяющего (`averageVerifierPunctuality` и др.) вызов `float(None)` роняет процесс проверки пира с исключением `TypeError`.
  - *Исправление:* Добавлены функции безопасного приведения `_safe_float()` и `_safe_int()` с фолбэком на `0.0`/`0`.

- [x] **[HIGH] Блокировка SQLite базы данных и пропуск флага `is_manual` при UPSERT (`app/storage.py`)**
  - *Описание:* Параллельные обращения из Telegram-хендлеров и фонового потока проверки вызывают `sqlite3.OperationalError: database is locked`. В вызове `save_peers_batch` выражение `ON CONFLICT DO UPDATE` не обновляло колонку `is_manual`.
  - *Исправление:* Включен WAL-режим (`PRAGMA journal_mode=WAL;`), установлен `timeout=30.0` при подключении и скорректировано выражение `is_manual=CASE WHEN excluded.is_manual = 1 THEN 1 ELSE is_manual END`.

- [x] **[HIGH] Отсутствие повторных попыток при 5xx ошибках API и избыточные TCP-соединения (`app/s21_api.py`)**
  - *Описание:* Каждый HTTP-запрос создавал новое TCP/TLS соединение вместо переиспользования `requests.Session()`. Серверные ошибки 5xx падали сразу на первой попытке. Повтор после 401 на последней попытке не выполнял запрос заново.
  - *Исправление:* Клиент переведен на `requests.Session()`, добавлена поддержка повторных попыток при 5xx HTTP ошибках и сбоях сети с экспоненциальной задержкой, исправлен логика ретрая при 401.

- [x] **[MEDIUM] Утечка временных директорий экспорта и дублирование записи в БД (`app/bot.py`)**
  - *Описание:* Временные директории `tempfile.mkdtemp()`, создаваемые при экспорте и генерации отчетов, не удалялись с диска при ошибках. В `run_check_and_notify` выполнялось дублирующее сохранение всех пиров вызовом `save_peers_batch`.
  - *Исправление:* Работа с временными папками обернута в `try...finally` с `shutil.rmtree(temp_dir, ignore_errors=True)`, дублирующий вызов `save_peers_batch` удален.

- [x] **[MEDIUM] Падение Markdown-разметки Telegram на логинах со спецсимволами (`app/bot.py`)**
  - *Описание:* Отправка сообщений с `parse_mode="Markdown"`, содержащих логины или название трайбов с символами (например, `john_doe_21`), вызывала ошибку API Telegram `400 Bad Request: Can't parse entities`.
  - *Исправление:* Реализована функция экранирования спецсимволов Markdown `escape_markdown()`.

- [x] **[MEDIUM] Зависание inline-кнопок и отсутствие отклика на `/check_now` (`app/bot.py`)**
  - *Описание:* При обращении к callback-хендлеру с некорректными данными не вызывался `answer_callback_query`, из-за чего на кнопках бесконечно вращался индикатор загрузки. Вызов `/check_now` во время уже выполняющейся проверки не информировал пользователя.
  - *Исправление:* Добавлен обязательный вызов `answer_callback_query` с текстом ошибки и информирование пользователя в `/check_now`, если проверка уже активна.

- [x] **[LOW] Падение при пустых строках в `.env` и неотправка сигнала остановки потока (`app/config.py`, `app/main.py`)**
  - *Описание:* Наличие пустых значений (например, `CHECK_INTERVAL_MINUTES=`) в `.env` приводило к вызову `int("")` и падению при импорте. При остановке бота по `KeyboardInterrupt` фоновый поток проверки не останавливался корректно.
  - *Исправление:* Реализованы функции `_get_env_int` и `_get_env_float` с безопасным дефолтом, добавлен вызов `stop_event.set()` при завершении бота.

- [x] **[LOW] Добавление юнит-тестов для новых сценариев и граневых случаев (`tests/`)**
  - *Описание:* Существующее покрытие тестами не содержало тестов на `null` значения фидбека, режим WAL SQLite, экранирование Markdown и очистку временных директорий.
  - *Исправление:* Набор автотестов расширен до 16 успешных проверок.
