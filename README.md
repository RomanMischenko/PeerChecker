# School 21 PeerChecker Telegram Bot

Автоматизированный Telegram-бот на Python (`pyTelegramBotAPI`) для мониторинга, валидации и фильтрации новых пиров (студентов) Школы 21 (School 21) по заданным коалициям (трайбам) для кампуса в Нижнем Новгороде.

---

## Основные возможности

- **Автоматический поиск новых пиров:** Периодический запрос списков участников целевых коалиций через OpenAPI Школы 21.
- **Гибкая привязка проектов к волне (`TARGET_PROJECT_IDS_<WAVE>`):** Проекты задаются отдельно для каждой волны в переменных окружения (например, `TARGET_PROJECT_IDS_26_04_NN`). При отсутствии настроенных проектов или ошибках API пир переводится в статус `SKIPPED_PEERS` с детализацией причины.
- **Дедупликация и оптимизация запросов:** Участники, ранее сохраненные в локальной базе данных SQLite, **не проверяются повторно** при последующих прогонах и перезапусках бота.
- **Сохранение состояния при перезапуске:** Статус фонового мониторинга сохраняется в таблице `bot_state` базы данных SQLite. При перезапуске или аварийном завершении работы бот автоматически возобновляет фоновый мониторинг без необходимости повторного вызова `/start_monitoring`.
- **Эвристическая валидация:** Автоматическое разделение новых учеток на `VERIFIED` (успешно сдано минимум 3 проекта из целевого списка и получены положительные оценки проверяющего в фидбеке) и `SUSPICIOUS` (неактивные/тестовые учетки с выводом причин подозрения).
- **Отслеживание отчислившихся пиров (`EXPELLED`):** При каждой проверке бот сравнивает актуальный список участников коалиций из API со списком пиров в локальной БД. Если ранее сохраненный пир (в любом активном статусе) отсутствует в ответе API, его статус автоматически меняется на `EXPELLED` и администратору приходит уведомление с файлами `<tribe>_expelled.txt`. Если отчислившийся пир впоследствии возвращается в коалицию, он автоматически перепроверяется и восстанавливается в актуальный статус (`VERIFIED`, `SUSPICIOUS` или `SKIPPED_PEERS`). Пир одновременно принадлежит ровно одному статусу.
- **Ручная модерация статусов:** Администратор может изменить статус пира нажатием инлайн-кнопки в карточке пира `/peer <login>`. Ручной статус защищен от перезаписи автопроверкой.
- **Отчеты с вложениями:** При обнаружении новых или отчислившихся пиров бот отправляет сводку в Telegram-чат и прикрепляет `.txt` файлы с разбивкой по трайбам (`<tribe>_verified.txt`, `<tribe>_suspicious.txt` и `<tribe>_expelled.txt`).
- **Расширенное логирование с ротацией:** Ведение суточной ротации лог-файлов (`TimedRotatingFileHandler`) с хранением истории за последние 30 дней и фильтрацией системного шума библиотеки Telegram.
- **Авторизация по Telegram ID:** Выполнение команд доступно только Telegram-пользователям, указанным в `TELEGRAM_ADMIN_IDS`.

## Варианты запуска

### 1. Деплой на удаленный сервер (VPS / Docker Compose) — Рекомендуемый

1. Склонируйте репозиторий на сервер:
   ```bash
   git clone https://github.com/your-username/PeerChecker.git
   cd PeerChecker
   ```
2. Настройте переменные окружения:
   ```bash
   cp .env.example .env
   nano .env  # Укажите реальные ключи и логин/пароль S21
   ```
3. Запустите контейнер в фоновом режиме:
   ```bash
   docker compose up -d --build
   ```
4. Проверьте логи работы:
   ```bash
   docker compose logs -f peerchecker
   ```

---

### 2. Локальный запуск для разработки (без Docker)

1. Требуется Python 3.11+.
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Укажите параметры в `.env`.
5. Запустите бота:
   ```bash
   python -m app.main
   ```

## Команды Telegram бота

- `/start`, `/help` — Приветствие и список команд.
- `/start_monitoring` — Запуск фонового мониторинга (интервал задается `CHECK_INTERVAL_MINUTES`).
- `/stop_monitoring` — Остановка фонового мониторинга.
- `/check_now` — Запуск мгновенной проверки пиров вне очереди.
- `/status` — Текущий статус работы бота, дата последней проверки и статистика БД.
- `/peers [verified|suspicious|skipped_peers|expelled|all|tribe]` — Получение текущего списка пиров из БД (с фильтрацией).
- `/export` — Экспорт текущих пиров в `.txt` файлы по трайбам (verified, suspicious, expelled).
- `/peer <login>` — Просмотр карточки пира с кнопками быстрой смены статуса (`[ VERIFIED ]` / `[ SUSPICIOUS ]` / `[ EXPELLED ]`).
- `/recheck <login>` — Ручная перепроверка пира через API S21 с обновлением данных и статуса в БД.
