# Трекер багов и недоработок PeerChecker (BUGS.md)

В данном файле отслеживается статус исправления выявленных багов и недоработок.

---

## 🐛 Список багов и статус исправления

- [x] **BUG-01: Некорректные повторные попытки (retries) при 400/403/404 ошибках в `s21_api.py`**
  - *Описание:* Метод `_request()` при получении неперехватываемых статус-кодов (например, 404 Not Found или 403 Forbidden) перехватывал `requests.HTTPError`, но при `attempt < max_retries` не выбрасывал исключение сразу, заставляя API делать бесполезные повторные запросы.
  - *Решение:* Выбрасывать `S21ApiError` сразу для статусов, не являющихся 429/5xx, не тратя попусту лимиты запросов.

- [x] **BUG-02: Переусложнённое получение XP и избыточные сетевые запросы истории в `validator.py`**
  - *Описание:* При валидации пира вызывался метод `get_participant_xp_history` и цепочка логических операторов `or`, которая пропускала значение `0` XP.
  - *Решение:* Считывать точный атрибут `expValue` напрямую из профиля `info.get("expValue")`, избавившись от лишнего сетевого вызова `get_participant_xp_history`.

- [x] **BUG-03: Искажение статистики базы данных в `/status` из-за статуса `SKIPPED_WAVE` в `storage.py`**
  - *Описание:* В `Storage.get_stats()` все пиры со статусом `SKIPPED_WAVE` попадали в ветку `else:`, из-за чего учитывались как `suspicious` (подозрительные).
  - *Решение:* Добавлен отдельный агрегатор `total_skipped_wave` в `get_stats()`.

- [x] **BUG-04: Молчаливое завершение команды `/export` без отправки ответа в `bot.py`**
  - *Описание:* Если в БД присутствовали только пиры со статусом `SKIPPED_WAVE`, списки `verified` и `suspicious` оказывались пустыми, файлы не генерировались, и администратор не получал ответа.
  - *Решение:* Отправляется информационное сообщение администратору при отсутствии данных категорий VERIFIED/SUSPICIOUS.

- [x] **BUG-05: Лишние обратные слэши `\` внутри моноширинных блоков Telegram Markdown v1 в `bot.py`**
  - *Описание:* Функция `escape_markdown()` заменяла `_` на `\_`. При вставке внутри обратных кавычек (`` `...` ``) Telegram отображал слэши буквально (например, `` `26\_08\_NN` ``).
  - *Решение:* Создан отдельный форматтер `escape_code_block` для использования внутри кавычек без использования бэкслешей.

- [x] **BUG-06: Отсутствие локального отлова ошибок отправки сообщений Telegram API при вызове команд в `bot.py`**
  - *Описание:* Ошибки сети или Telegram API в командах `/peer`, `/peers`, `/export` и `/set_status` приводили к необработанному исключению.
  - *Решение:* Команды бота обёрнуты в `try/except` с информированием администратора в случае ошибки.

- [x] **BUG-07: Потенциальная гонка потоков при рестарте фонового мониторинга в `bot.py`**
  - *Описание:* При тайм-ауте `join(timeout=3.0)` старый поток мониторинга мог остаться активным.
  - *Решение:* Добавлена проверка совпадения текущего потока с `self.monitoring_thread` внутри `run_check_and_notify` и цикла мониторинга.
