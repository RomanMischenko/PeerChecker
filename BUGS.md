# Отслеживание исправлений багов (Bug Tracker)

Данный файл содержит список выявленных недоработок и багов в проекте PeerChecker. Статус исправления отслеживается флагами `[ ]` (не исправлено) и `[x]` (исправлено).

## Список багов

- [x] **BUG-01: Ложное уведомление и отсутствие обработки ошибок в callback-кнопках `set_status`**
  - **Описание:** В `app/bot.py` обработчик inline-кнопок `handle_status_callback` не обрабатывает возможные ошибки от `update_peer_status` (например, `ValueError`) и сообщает об успешном изменении статуса, даже если пир отсутствует в БД (`update_peer_status` вернул `False`).
  - **Файл:** `app/bot.py`

- [x] **BUG-02: Фильтрация по статусу `SKIPPED_WAVE` в команде `/peers`**
  - **Описание:** Команда `/peers` считает допустимыми статусами только `VERIFIED` и `SUSPICIOUS`. Фильтр `/peers SKIPPED_WAVE` ошибочно воспринимает `SKIPPED_WAVE` как название трайба, возвращая 0 пиров.
  - **Файл:** `app/bot.py`

- [x] **BUG-03: Отсутствие отображения `skipped_wave` по трайбам в команде `/status`**
  - **Описание:** В статистике `/status` для каждого трайба выводятся только `verified` и `suspicious`, но не выводится `skipped_wave`, из-за чего сумма элементов не совпадает с общесистемным значением `total`.
  - **Файл:** `app/bot.py`

- [x] **BUG-04: Некорректный сброс длины чанка в `chunk_text` для длинных строк**
  - **Описание:** В `app/bot.py` при разбиении строк длиннее `max_length` не сбрасываются служебные переменные длины текущего чанка, что ведет к некорректной нарезке сообщений.
  - **Файл:** `app/bot.py`

- [x] **BUG-05: Некорректная обработка ретрая 401 Unauthorized на последней попытке в `S21ApiClient`**
  - **Описание:** В `app/s21_api.py` при ретрае по 401 ошибке на последней попытке повторный HTTP-запрос выполняется вне рамок логики попыток и обратной задержки.
  - **Файл:** `app/s21_api.py`

- [x] **BUG-06: Логирование ошибок валидации пира без стектрейса**
  - **Описание:** В `run_check_and_notify` ошибки валидации пира записываются в лог через `logger.error` без параметра `exc_info=True`, затрудняя диагностику при сбоях API.
  - **Файл:** `app/bot.py`

- [x] **BUG-07: Отсутствие retry-механизма при возможной блокировке SQLite DB (`database is locked`)**
  - **Описание:** В `app/storage.py` операции обновления статусов и логирования проверок не имеют устойчивой обработки повторных попыток при конкурентном доступе.
  - **Файл:** `app/storage.py`
